# Бот: расписание на завтра/неделю + еженедельная автоотправка с закреплением

Изменение от 23.11.2026. Файлы: `app/bot.py`, `app/models.py`.
Коммиты: `2cb3085` (фича), `d512a71` (CHANGELOG о деплое).

## Что добавлено

### Кнопки режима группы

- **Клавиатура группового режима** (`group_menu()`): `/start` в группе показывает
  «📅 Расписание на сегодня», «📅 Расписание на завтра», «🗓 Расписание на неделю»,
  «⚙️ Настройки». Приватное меню (`main_menu`) не изменилось.
- **Команды-дубли** (работают и в личке, и в группе):
  - `/tomorrow` (`/zavtra`) — расписание на завтра; «завтра» корректно
    пересекает границу недели (запрос по `period_start = week_monday(завтра)`),
    воскресенье → «Воскресенье — занятий нет».
  - `/week` (`/nedelya`) — расписание на текущую неделю с заголовком
    `🗓 Расписание на неделю {fmt_week(monday)}` (напр. «23.11–28.11.2026»).
- **Лимит Telegram 4096**: недельное сообщение делится на части ≤3500 симв.
  `_split_html_chunks()` режет строго по границам строк — HTML-теги не рвутся.
- Рефакторинг: построение текста дня вынесено в `_day_schedule_lines(session, d)`
  (его используют «сегодня», «завтра»), недели — в `_week_schedule_chunks(session, monday)`
  (команда `/week` и еженедельная отправка).

### Настройки группы и таблица `chat_settings`

- **`/settings`** (или кнопка «⚙️ Настройки»): в приватном чате — подсказка,
  что настройка групповая; в группе — инлайн-переключатель
  «✅/❌ Еженедельная отправка: вкл/выкл» (`callback_data='grp:weekly'`).
- **Права**: менять настройку могут админы группы —
  `context.bot.get_chat_administrator(chat_id, tg_id)` (`BadRequest` → не админ) —
  или админ приложения (`User.role == 'admin'`).
- **Модель** `app/models.py` → таблица `chat_settings` (создаётся `create_all`
  при старте, миграция не нужна):
  - `chat_id` (PK) — идентификатор чата;
  - `weekly_schedule` (bool, default false) — включена ли автоотправка;
  - `pinned_message_id` — последнее закреплённое сообщение;
  - `last_weekly_monday` — понедельник, за который уже отправили (защита от дублей).
- `_chat_settings(session, chat_id)` — get-or-create строки настроек.
- Переключатель: `on_group_callback` (`CallbackQueryHandler`, pattern `^grp:`);
  после нажатия сообщение редактируется (BadRequest «message is not modified»
  игнорируется), `query.answer()` — во всех ветках.

### Еженедельная автоотправка (пн 00:00) + закрепление

- **`_weekly_loop`** — фоновый цикл по образцу `_resend_loop` (досылка пожеланий):
  стартует в `_post_init` через `application.create_task`, тик каждые 5 минут.
- **`_weekly_send(bot)`** — идемпотентная «догоняющая» схема без абсолютных
  таймингов: на каждом тике берёт все `ChatSettings` с `weekly_schedule=True`,
  у которых `last_weekly_monday IS NULL OR < текущий понедельник`, и отправляет.
  - Первый тик на/после понедельника 00:00 и есть отправка «в 00:00 понедельника».
  - **Рестарт хостинга безопасен**: если бот упал в воскресенье и поднялся
    в среду — отправит пропущенную неделю ровно один раз и обновит
    `last_weekly_monday`.
- Отправка: первая часть — через `_send_telegram` (сеты/ретраи как раньше),
  остаток — следом; затем `unpin_chat_message` старого закреплённого (если было)
  и `pin_chat_message(first_msg, disable_notification=True)`.
- **`_send_telegram` теперь возвращает `Message`, а не `True`** — нужен
  `message_id` для закрепления. Все старые вызовы проверяют truthiness —
  совместимо.

## Что нужно сделать руками (один раз)

1. **Назначить бота администратором группы** — иначе закрепление не сработает
   (`pinChatMessage` требует прав). Без прав бот пришлёт расписание, но вместо
   закрепления отправит в чат: «⚠️ Не удалось закрепить расписание — сделайте
   бота администратором группы». Отправка/`last_weekly_monday` при этом
   фиксируются, повторной попытки закрепления не будет до следующего понедельника.
2. В группе: `/settings` → «Еженедельная отправка: вкл».
3. Privacy mode (`/setprivacy` у BotFather → Disable) уже требуется для
   кнопок режима группы — см. `docs/bot-groups.md`.

## Нюанс: пуш в GitHub (исправлен этим же вечером)

- PAT, вшитый в `origin` remote, истёк (API отдавал 401) — git при пуше
  падал с «could not read Username».
- Дополнительно: на рабочей машине `github.com` резолвится в fake-IP
  локального прокси (198.18.0.0/15); git-транспорт получает 301-редирект
  и **теряет токен из URL** → «unexpected disconnect». Прямой curl с
  `AUTHORIZATION: basic base64(x-access-token:<PAT>)` отвечает 200.
- Починено: `origin` переведён на чистый URL (без токена), credential helper
  читает `$GITHUB_PERSONAL_ACCESS_TOKEN` из окружения. Если пуш снова
  попросит имя пользователя — проверять сначала валидность токена
  (`curl -H "Authorization: Bearer $TOKEN" https://api.github.com/user`).

## Проверка после деплоя

- В группе нажать «🗓 Расписание на неделю» — придёт вся неделя по дням
  (пустые дни — «Занятий нет.»).
- «📅 Расписание на завтра» — расписание следующего дня (в воскресенье —
  «Воскресенье — занятий нет.»).
- `/settings` — переключатель; после переключения текст кнопки меняется.
- Следующий понедельник 00:00 — расписание приходит в группу и закрепляется;
  повторный рестарт бота до/после не даёт дубля.
