# Сайт: объявления-баннеры на всех страницах

Изменение от 23.11.2026. Заметные объявления для всех посетителей: поверх
навигации на каждой странице, с закрытием, которое запоминается в браузере
пользователя.

Файлы: `app/models.py` (модель `Announcement`), `app/__init__.py`
(context processor), `app/admin.py` + `app/templates/admin/announcements.html`
(CRUD), `app/templates/base.html` (баннер + JS), `app/templates/admin/dashboard.html`.

## Как работает

- **Модель:** `announcements` — `title` (необязателен), `text` (Markdown,
  обязателен), `is_active`, `created_at`. Таблица создаётся `create_all`.
- **Показ:** context processor `_inject_announcements` в `create_app()`
  отдаёт активные объявления (`created_at` по убыванию) во все шаблоны.
  Обёрнуто в try/except: при сбое БД страницы рендерятся без баннера,
  а не падают.
- **Баннер** (`base.html`, над navbar): `alert-warning alert-dismissible`,
  заголовок жирным, текст через `{{ a.text | md }}` (таблицы поддерживаются,
  bleach санитизирует), дата мелко. Один блок на каждое активное объявление.
- **Закрытие — в браузере:** небольшой inline-JS после баннеров читает
  `localStorage['seenAnnouncements']` (JSON-массив id) и сразу прячет
  уже закрытые; клик по × добавляет id в массив. То есть объявление
  «мозолит глаза», пока **каждый конкретный пользователь** его не закроет.
- **Деактивация в админке** убирает баннер для всех сразу (в отличие от
  localStorage-закрытия, которое индивидуально).

Механика выбрана без учёта пользователей на сервере: сайт в основном
посещают анонимно, поэтому «кто ознакомился» отслеживается на стороне
браузера, а не в БД.

## Админка

`/admin/announcements` (все POST — CSRF из сессии):

| Действие | Маршрут |
|---|---|
| Список (активные сверху, новые выше) | GET `/admin/announcements` |
| Создать | POST `/admin/announcements/create` |
| Правка (инлайн-форма) | POST `/admin/announcements/<id>/edit` |
| Вкл/выкл тумблером | POST `/admin/announcements/<id>/toggle` |
| Удалить | POST `/admin/announcements/<id>/delete` |

На дашборде — карточка со счётчиком (жёлтая рамка, если есть активные)
и ссылка «Объявления на сайте» с бейджем активных.

## Проверка

Staging на хосте (`~/.stage`, боевой `.env`): создание через POST,
появление баннера на `/`, `/session`, `/changes`, `/week`, Markdown-жирный
в рендере, тумблер прячет, удаление чистит. Бэкап деплоя:
`~/schedule_app/.backup/2026-11-23-1320/app.tgz`.

## Нюансы

- Текст рендерится тем же `md`-фильтром, что и ДЗ/примечания: расширения
  `nl2br`, `sane_lists`, `tables`; разрешённые теги — см.
  `app/markdown_render.py`.
- Баннеры рендерятся видимыми и прячутся JS сразу после — один кадр
  «мигания» для уже закрывших допустим, зато нет скачка вёрстки (CLS).
- Деактивация/активация мгновенная — без кэширования запроса объявлений.
